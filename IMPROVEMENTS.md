# What I Would Improve With Another Week

With another week, I would first create a labelled evaluation set from real patient questions and measure retrieval recall, answer faithfulness, citation precision, and unknown-answer accuracy. The current BM25 index is intentionally simple and transparent for seven pages; I would compare it with hybrid retrieval that combines BM25 and multilingual embeddings, then keep the simpler system unless the measured improvement justified the added complexity. I would also add a reranker and passage-level metadata for treatment, country, currency, package type, and “included versus excluded” status. That would make cost comparison and package questions more deterministic.

For production operations, I would move unanswered-question logs from JSONL to a durable database, add an authenticated dashboard for content gaps, schedule monitored refreshes, retain prior knowledge snapshots for rollback, and alert when extraction changes unexpectedly. I would also add rate limiting, structured request tracing, and provider-failure metrics. Finally, I would expand adversarial tests for prompt injection in scraped content, conflicting prices, stale dates, multilingual questions, and follow-ups that switch treatment or country.

Known limitations today are that extraction quality depends on the source HTML and a small amount of template noise can remain; BM25 is lexical and may miss paraphrases; safe extractive mode is less conversational than the LLM path; multilingual answer quality depends on the configured LLM; and unanswered-question logging is file-based, which is not durable on hosts with ephemeral filesystems. The app deliberately prefers saying it does not know over guessing when any of those limitations reduce confidence.
